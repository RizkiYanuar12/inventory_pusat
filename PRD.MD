# PRD — SS_Inventaris: Pesan → Kirim → Terima

## 1. Latar
- Outlet pesan via WA + spreadsheet manual → lambat, human error, tidak terlacak.
- Gudang kirim tanpa bukti terima terstruktur.
- Tujuan: 1 aplikasi web, link unik per outlet/pengiriman, dengan login (gudang 1 kredensial bersama + outlet username+password per link).

## 2. User & Role
- Admin Gudang: kelola stock, lihat pesanan, approve/tolak (per pesanan & per item), tandai dikirim / batalkan pengiriman, monitoring terima.
- Outlet: pesan barang + konfirmasi terima via link permanen (wajib login password — link saja tidak cukup).
- Non-goal: PIN/OTP terpisah, expiry token kirim, multi-gudang, harga/faktur, aplikasi kedua untuk outlet. (Login outlet DIKELUARKAN dari non-goal 2026-09-13.)
- 1 link: link permanen outlet `/pesan/<slug>-<token8>` (permanen: form pesan + riwayat + Tab Surat Jalan; token = identitas, password = gerbang — buka link WAJIB login dulu; tutup tab = sesi hilang). Route `/terima/<token>` link-only DICABUT total 2026-09-20 (surat jalan hanya Tab Surat Jalan di balik login; tanpa link cadangan, tanpa Salin Link, tanpa Kirim WA).

## 3. Alur
- P1 Pesan: outlet buka link permanen `/pesan/<slug>-<token>` → Tab `Pesan Baru` (keranjang tanpa angka stock, di atas search bar) → submit → `Pesanan/BARU` + info batch masuk & rencana kirim otomatis → popup sukses + otomatis pindah ke Tab `Riwayat`.
- P1b Loket jam + gabung sehati (Ganti 2026-09-14, aturan 1-aktif 2026-09-09 DICABUT): loket pesan buka tiap hari di bawah jam 15:00 WIB, kunci total di atasnya (backend `403` + frontend kartu info, pesan persis: `Hanya menerima pesanan di bawah jam 15.00 WIB`). Selama loket buka, outlet boleh pesan berkali-kali; pesan di hari-Jakarta yang sama menempel ke order `BARU` hari itu juga (ID sama, item se-ID dijumlah, respons `digabung: true` + lonceng `PESANAN DIGABUNG`). Hanya `BARU` yang boleh ditempel (yang sudah diputus melahirkan pengiriman + potong stock). Beda hari atau tak ada `BARU` sehati → ID baru. Tidak ada jalur susulan (dicabut 2026-09-14).
- P1c SOP batal oleh outlet (Terkunci 2026-09-09): outlet TIDAK punya tombol batal; yang mau membatalkan hubungi gudang via WA/telpon → gudang eksekusi Tolak semua item + `Alasan Tolak` (→ `DITOLAK` terminal → blokir lepas → boleh pesan ulang). Tidak ada status BATAL terpisah; `DITOLAK` merangkap fungsi batal.
- P2a Kirim (jalur setuju): gudang approve per item (Penuhi / Tolak per item + keterangan manual) → status `DISETUJUI` (semua dipenuhi) / `DISETUJUI SEBAGIAN` (ada yang ditolak, ada yang dipenuhi) → sistem OTOMATIS membuat record pengiriman berisi item dipenuhi (**stock kurang 1x di titik ini**, atomik dengan approve; TIDAK ada tombol "Buat Pengiriman" manual) → status internal `SIAP KIRIM` (belum terlihat outlet) → gudang klik manual `Tandai Dikirim` (popup konfirmasi "paket sudah diserahkan?") → `DIKIRIM`: surat muncul di Tab Surat Jalan outlet (sebelumnya "belum dikirim"; tanpa link, tanpa tombol share — DICABUT 2026-09-20).
- P2a-R Batal kirim (mundur 1 langkah): selama outlet BELUM submit laporan, gudang boleh `Batalkan Pengiriman` (tombol sekundar + popup alasan wajib) → kembali `DISETUJUI`/`DISETUJUI SEBAGIAN` semula (tanpa link lama — route `/terima` sudah dicabut), stock tidak diutak-atik, jejak minimal di kolom `RiwayatStatus`. Setelah outlet `DITERIMA`/`DITERIMA SEBAGIAN` → kunci mati, tidak bisa mundur. Tidak ada edit status bebas/dropdown.
- P2c Mirror Pesanan (Terkunci 2026-09-09): baris `Pesanan` mengikuti peristiwa `Pengiriman` (best-effort; sumber kebenaran tetap `Pengiriman`): `Tandai Dikirim` → `DIKIRIM`; `Batalkan` → asal semula (ada TOLAK = `DISETUJUI SEBAGIAN`, else `DISETUJUI`); laporan terima → `DITERIMA`/`DITERIMA SEBAGIAN` (terminal).
- P2b Tolak (jalur terminal): semua item ditolak → `DITOLAK` + keterangan per item (tanpa alasan umum terpisah) → **berhenti, tanpa pengiriman, tanpa kurang stock**. Outlet lihat keterangan per item di Tab Riwayat link permanen, pesan ulang bila masih butuh.
- P3 Terima: outlet ceklis per item sesuai/tidak + jumlah terima + keterangan jika beda + nama penerima → submit → `DITERIMA` / `DITERIMA SEBAGIAN`, halaman terkunci. Gudang read-only (hanya terima info, tidak ada tombol konfirmasi terima).

## 5. Data (Supabase + CSV — Terkunci 2026-09-10)
- Gudang di Supabase, diisi via migrasi CSV (`Kertas Kerja Pengadaan F&B - DATA GUDANG PUSAT.csv`); tanpa kolom bulan/tanggal — tiap sel in/out → 1 baris `transaksi` bertanggal (peta: SO 12 Agu 2026; harian 13 Agu–10 Sep 2026).
- `barang_inventory`: `id_barang` (PK, auto `MNL-0001…` urut global 4-digit) | `nama_barang` (`ITEM`) | `varian` | `kategori_bahan` | `satuan` (acuan UNIT SO) | `satuan_gudang` + `isi_per_gudang` (NULL = tanpa pasangan) | `total` (satu-satunya sumber stock) | `divisi` | `keterangan` (catatan murni) | `minimum_stock` | `istilah_data_resep` (alias) | `dibuat_pada`. SO 12 Agu tersimpan sebagai baris saldo-pembuka di `transaksi` (12 Agu 2026 00:00).
- `transaksi`: `id_transaksi` (identity PK) | `id_barang` (FK RESTRICT) | snapshot `nama_barang/varian/kategori_bahan` | `jenis` (Masuk/Keluar) | `jumlah` (numeric) | `satuan` | `harga_satuan` (jejak nilai per satuan; NULL = lama/belum berhHarga) | `dibuat_pada`.
- Data outlet (tetap, pindah ke Supabase 2026-09-10, Sheet dihapus total): tabel `outlet` (`slug` PK | `token` UNIQUE | `outlet` | `username_outlet` UNIQUE NULL (pre-set gudang 1x, wajib terisi agar bisa masuk) | `password_outlet` NULL=scrypt (NULL = klaim-pertama via link)) + kontrak `Pesanan`/`Pengiriman` di bawah — halaman pesan mengembalikan baris milik token itu via filter `token_outlet` di layer API, hanya dengan sesi login valid.
- Data gudang (2026-09-14; penuh 2026-09-14, tahap 2 terserap): 1 kredensial bersama (2 orang) di tabel `gudang` — 1 baris tetap `id=1` (`id` INT PK selalu 1 | `password_gudang` TEXT `scrypt$salt$hash`, bukan plaintext | `created_at`). Seed awal via SQL developer; aplikasi hanya `UPDATE ... WHERE id=1` (ganti via UI wajib sesi). Sesi gudang (`sesi_gudang`, opaque 24 jam) = satu-satunya kunci: SEMUA halaman + endpoint gudang wajib sesi; login sekali → semua tab terbuka. Jalur outlet `/pesan/*` + API-nya (`/api/pesan/*`) wajib sesi outlet; tak ada lagi jalur outlet publik tanpa login (route `/terima` DICABUT 2026-09-20). Kill-switch `GUDANG_GATE=off` dipertahankan (termasuk guard frontend via `/api/gudang/sesi`). Mendarat pasca-login: `/homepage` (atau halaman yang dituju semula).
- `Pesanan`: ID Pesan, SlugOutlet, TokenOutlet, Outlet, TanggalPesan (`Selasa, 08 September 2026 pukul 08.05 WIB`), BatchMasuk (`Kamis, 10 September 2026`), RencanaKirim, Status (BARU/DISETUJUI/DISETUJUI SEBAGIAN/DITOLAK/SIAP KIRIM/DIKIRIM/DITERIMA/DITERIMA SEBAGIAN), Items JSON [{id, nama, varian, satuan, qtyPesan, keputusan: PENUHI/TOLAK, qtyKirim, keterangan}], Ringkasan, AlasanTolak, RiwayatStatus.
- `Pengiriman`: ID Kirim (KRM-YYYYMMDD-NNN), Token (kolom legacy, selalu kosong sejak 2026-09-20 — surat jalan via sesi login + `idKirim`, tanpa token kirim), ID Pesan ref, Tanggal Buat, Tanggal Kirim, Outlet, Status (SIAP KIRIM/DIKIRIM/DITERIMA/DITERIMA SEBAGIAN), Items JSON [{id, nama, jumlahKirim, jumlahTerima, ceklis, keterangan}], Ringkasan, Nama Penerima, Tanggal Terima, RiwayatStatus.
- Format waktu baku: timestamp = `Hari, DD Bulan YYYY pukul HH.MM WIB`; tanggal slot = `Hari, DD Bulan YYYY` tanpa jam. WIB Asia/Jakarta, konsisten dengan `dateParse` (detik opsional).
- Kolom `Items JSON` = sumber mesin (app `JSON.parse`); kolom `Ringkasan` = terjemahan manusiawi diisi backend otomatis, contoh: `Susu Greenfield 250ml x10 (Penuhi); Gula Pasir 1kg x5 (Tolak: habis)`. Non-teknis baca `Ringkasan`, app baca JSON.

## 6. API
- `GET /api/pesan/:token` (wajib cookie sesi login; slug diabaikan), `POST /api/pesan/:token` (wajib sesi; auto-hitung batch/kirim).
- `POST /api/pesan/:token/masuk` (publik, rate-limit: `{username, password}` → cookie sesi bila cocok; 401 generik bila salah; NULL → 401 + flag buat-pertama).
- `POST /api/pesan/:token/password-awal` (publik, hanya bila `password_outlet` NULL + username cocok: `{username, password, konfirmasi}` min 4 + sama, auto-masuk → scrypt; terisi → 409 terkunci).
- `POST /api/gudang/masuk` + `POST /api/gudang/keluar` + `GET /api/gudang/sesi` + `POST /api/gudang/password` (selalu wajib sesi gudang; awal via SQL developer).
- ~~`POST /api/pesanan/gudang`~~ — TIDAK PERNAH DIBUAT (deviasi T2d tercatat; Tab Buat memakai endpoint outlet yang sama, lalu dicabut bersama F2).
- `GET /api/pesanan`, `POST /api/pesanan/:id/keputusan` (per item + alasan; guard hanya dari BARU; urutan tulis: validasi stock semua penuhi → fungsi internal `buatPengiriman()` langsung → update Pesanan; saat disetujui otomatis buat record pengiriman + kurang stock 1x, tanpa endpoint buat-manual), `POST /api/pesan/:token/password` (wajib sesi outlet: ganti-sendiri), `POST /api/outlet/:slug/username` (wajib gudang: set 1x bila NULL), `POST /api/outlet/:slug/password` (gudang-internal: `{password, konfirmasi}` → scrypt, min 4 char).
- `GET /api/pengiriman`, `POST /api/pengiriman/:id/kirim` (manual SIAP KIRIM→DIKIRIM; tanpa token terima — token kirim DICABUT 2026-09-20), `POST /api/pengiriman/:id/batal-kirim` (hanya dari DIKIRIM + belum ada laporan + alasan wajib → kembali semula), `GET /api/pesan/:token/surat/:idKirim`, `POST /api/pesan/:token/surat/:idKirim/konfirmasi` (wajib sesi outlet; hanya dari DIKIRIM, tolak submit ganda; cek milik via `id_pesan.token_outlet`). Endpoint link-only `GET /api/pengiriman/:token` + `POST /api/pengiriman/:token/konfirmasi` DICABUT total 2026-09-20. Jalur approve pesanan (T2) memakai fungsi internal `buatPengiriman()` langsung (anti dobel-catat); tidak ada endpoint buat-manual.
- Aturan: validasi stock saat kirim, token outlet 8 char acak permanen (token kirim 128-bit DICABUT 2026-09-20 — surat jalan via sesi login + `idKirim`). Tab Kelola Akun (`Slug | Outlet | username | link pesan`, tanpa WA/nama orang — identitas orang = ketikan bebas per transaksi). Loket pesan: buka < 15:00 WIB tiap hari (tutup → 403 pesan persis); gabung ke BARU sehati (`digabung: true`).

## 7. Jadwal Slot (Terkunci)
- Slot: Senin & Kamis, cutoff 15:00 WIB (Asia/Jakarta). Gudang hanya memproses & mengirim di hari slot.
- `batchMasuk` = slot terdekat >= waktu pesan (hari slot tapi >= 15:00 → slot berikutnya; non-slot → slot berikutnya).
- `rencanaKirim` = slot berikutnya setelah `batchMasuk`.
- Contoh: Senin 10:00 → masuk Senin → kirim Kamis; Senin 16:00 → masuk Kamis → kirim Senin depan; Selasa/Rabu → masuk Kamis → kirim Senin depan; Kamis 10:00 → masuk Kamis → kirim Senin depan; Kamis 16:00 / Jumat–Minggu → masuk Senin → kirim Kamis.
- Fungsi murni `hitungSlot(waktuPesan)` + self-check; 1 implementasi dipakai POST & GET.

## 9. Definisi DITERIMA SEBAGIAN (Terkunci)
- DITERIMA SEBAGIAN = berita acara mini outlet tentang barang fisik yang masuk vs yang dikirim (sistem menentukan otomatis, bukan dipilih manual).
- Semua item ceklis + jumlah terima = jumlah kirim → DITERIMA. Satu saja beda (kurang/lebih/varian keliru/tidak datang + keterangan) → DITERIMA SEBAGIAN.
- Konsumen: gudang (susulan/retur/komplain, manual per kasus) + arsip (nama penerima + tanggal + rincian per item).
